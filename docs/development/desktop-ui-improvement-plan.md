# StarAt 桌面客户端改进方案

审阅基线为 `7cdc100`，验证环境为 Windows / WebView2。先恢复快速捕获的原生回归覆盖，再处理输入法和桌面伙伴持久化，最后收口徽标可读性与阴影。

## 1. P2 · 统一快速捕获的提交契约

**建议保留当前表单行为。** 「新增事项」用底部「创建」按钮或 Ctrl+Enter 提交。标题框中的普通 Enter 保留草稿，正文继续支持换行和原有 Markdown 快捷键。Today 的单行快速输入继续用 Enter 提交。

原生 E2E 目前在打开「新增事项」后按普通 Enter，随后等待待办出现并超时。修改 [E2E 场景](../../tests/e2e/e2e.mjs)，用真实修饰键组合触发 [表单](../../apps/desktop/ui/src/features/quick-create/CreateConfiguration.tsx) 的快捷提交，补齐普通 Enter 保留草稿的断言。核对按钮、表单底部提示、引导和测试对提交键的描述。

**验收**：普通 Enter 保留标题草稿。Ctrl+Enter 和「创建」各只创建一条事项。提交后焦点还给之前的前台窗口。空草稿按 Esc 直接取消，有内容的草稿按现有确认流程取消。两者均不创建事项。

## 2. P2 · 统一中文输入法防护

[快速输入](../../apps/desktop/ui/src/features/quick-create/QuickCreateForm.tsx) 和完整表单主要检查 `isComposing`，[全局搜索](../../apps/desktop/ui/src/features/search/SearchPanel.tsx) 还检查键码 `229`。审阅发现的是条件差异，尚待真实输入法验证。

在会提交、打开结果或关闭草稿的键盘处理路径复用同一套组合态判定。先覆盖 `isComposing` 和 `229`，并用微软拼音记录 `compositionend` 与 Enter 的顺序。如果能复现该事件后的伴生 Enter，再加一次性拦截，验证它会及时清除并允许紧接着的主动 Enter。对完整表单保留 Markdown 处理优先级。

**验收**：选词使用 Enter 时，快速输入不创建事项，完整表单保留草稿，搜索不会打开结果。候选态 Esc 只关闭候选框。选词结束后，主动键入各入口规定的提交键，操作正常且只执行一次。浏览器事件测试覆盖组合态与键码分支，实际输入顺序用 Windows WebView2 和微软拼音验证。

## 3. P2 · 让桌面伙伴保存结果反映数据库状态

[皮肤存储](../../apps/desktop/ui/src/stores/skin-store.ts) 先写本地缓存，再发起数据库写入，当前会吞掉数据库错误。主窗口 [启动加载](../../apps/desktop/ui/src/main.tsx) 可能随后从数据库读到旧值。

继续复用现有设置 IPC 和缓存同步机制。主窗口可即时预览改动，数据库确认后再更新供另一窗口和启动使用的已保存值。串行提交并保留最新待保存快照，确保连续切换配色、表情或拖动帧速率时，旧请求不会覆盖新选择。写入失败时保留当前预览以便重试，显示明确的保存失败提示。旧格式有图片帧时依旧迁移为自定义图片模式。

**验收**：切换模式、款式和配色后，悬浮窗收到最新已保存值，重启与备份恢复结果一致。模拟 IPC 失败时设置页明确提示，并可重试。连续修改、失败后立即改选、旧图片皮肤恢复均有回归覆盖。

## 4. P3 · 提高徽标可读性，处理被隐藏的投影

把 [机器人角标](../../apps/desktop/ui/src/styles/global.css) 从 10px 提到 12px CSS 像素，保留等宽数字。先在现有 64×32 逻辑像素内调整角色与角标的相对位置，优先保证数字、护目镜和天线都能辨认。

上一轮原生阴影审计为 `cut: 0`，另报告机器人底部投影和快速捕获窗外阴影为 `hidden`。机器人投影可先试减小外扩量。快速捕获窗的外阴影如果在真窗始终不可见，可移除当前 `shadow-lg`。若设计需要可见外阴影，再把窗口余量、圆角内层和拖拽热区一起纳入变更。

**验收**：检查 0、9、99、99+、隐藏数量和完成态，在 100% 与 125% Windows 显示缩放下无重叠或裁切。重跑五种原生徽标尺寸矩阵，确认窗口与按钮边界匹配。用 `clip-audit.js` 检查静止、悬停、展开和快速捕获状态，要求 `cut: 0`，并人工复核 `hidden` 项。

## 实施与交付顺序

1. 对齐提交契约并恢复原生 E2E，再加入输入法回归用例。
2. 实现外观保存确认、失败和重试，验证跨窗口同步及备份恢复。
3. 调整角标与投影，更新收起态视觉基线，并复跑 200% 全局搜索缩放检查。

交付时记录 Windows / WebView2 版本、显示缩放、输入法验证结果、原生 E2E 回执和关键截图。

## 实施验证

- Windows build 26300，WebView2 157.0.4341.46，原生显示缩放 125%。真实键盘验证普通 Enter 保留标题，Ctrl+Enter 和按钮各创建一条，提交与取消后焦点归还，空草稿直接取消，非空草稿经确认后取消。
- 微软拼音实测覆盖完整表单、Today 单行输入和全局搜索。观察到组合开始前的 `Process` 键与键码 `229`。Today 和搜索中 Esc 取消组合，Enter 结束组合后输入仍保留焦点与文字。记录中没有出现组合结束后的额外 Enter，因此采用组合标志与键码防护。前端回归验证主动提交仍能执行。
- 皮肤写入失败、重试、连续改选和旧图片帧迁移通过前端回归。真实 SQLite 备份测试核对了恢复后的机器人设置。原生五种徽标尺寸矩阵通过，自定义图片在重启后、打开主窗口之前恢复为 88×40。
- 角标数字为 12px。浏览器 100% 和原生 WebView2 125% 下，0、9、99、99+ 均在 64×32 内且与角色分开。隐藏数字与完成态有组件回归覆盖。收起态截图回归已更新并通过。原生阴影审计的静止、悬停、展开、快速捕获和全局搜索为 `cut: 0`、`hidden: 0`，全局搜索 200% 缩放专项通过。
- 原生徽标矩阵在 Windows 100%（DPR 1）和 125%（DPR 1.25）下均通过。两种缩放下，五种徽标的窗口客户区均与按钮尺寸匹配，0、9、99、99+ 的 12px 角标均无重叠或裁切，隐藏数字和完成表情均通过。2026-11-15 补测 100% 后已恢复系统原来的 125% 显示缩放。
- 完整原生 E2E 在真实 OLE 拖放步骤报告 `NotStarted`。改动前的发布版在同机使用独立 OLE 场景也返回 `NotStarted`。本轮的捕获键盘、徽标和搜索使用独立结果验收。

### 重跑原生徽标验收

在对应 Windows 显示缩放下运行 `node tests/e2e/e2e.mjs --native --badge-only --badge-scale 100`，125% 时将最后一个参数改为 `125`。缩放不符会让用例失败。可用 `STARAT_EXE` 指定本次构建的可执行文件，用 `STARAT_E2E_EVIDENCE_DIR` 为各次运行分别保存截图与 `measurements.json`。
