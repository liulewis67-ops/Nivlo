# 悬浮框新增配置页实施文档

日期：2026-11-04。状态：开发完成，本机验证通过（2026-11-05）。

## 目标与现状

目前悬浮框的新增入口在 Today 面板底部展示单行标题输入，调用 quickCreate，失焦即取消。改为点击新增待办、笔记、提示或托盘快速添加后，在悬浮框所在显示器工作区中央打开完整配置表单。保存前只保留本地草稿，成功后恢复悬浮框原来的位置。

## UI/UX 方向（Impeccable）

本页属于 Operate 模式，是既有悬浮流程的扩展。沿用 PRODUCT.md、DESIGN.md 的中性色、蓝色主操作、系统字体、间距与输入组件，不更换视觉体系。

- 目标窗口 640×720 logical px，四周保留工作区边距；小屏幕缩小窗口，表单内容滚动，页头和保存栏始终可达。
- 页头明确“新增事项”，说明保存后创建；类型选择紧接页头，默认沿用被点击入口的类型。
- 内容区先标题和简述、详细内容及格式，再时间安排、提醒，再项目和优先级。笔记隐藏不适用字段，切换类型保留草稿。
- 时间输入显式区分计划与截止日期，未填日期时禁用时间；提醒将本地时间转换为 RFC3339。空白标题不能保存。
- 固定底栏有取消和创建；Ctrl+Enter 提交，普通 Enter 在多行框换行；处理输入法组合输入。
- 点击其他应用不丢失输入。取消有修改的草稿时在同页确认放弃，保存期间禁止取消及重复提交。错误在表单内显示并保留全部输入供重试。
- 页面已打开时托盘或全局快捷键再次请求新增：保留当前草稿和类型，只重新取得原生焦点并回到标题（放弃确认打开时回到“继续编辑”）。
- 底栏提供“创建后继续新增”：成功后不关闭，保留类型、计划日期、格式和项目，清空其余内容，显示“已创建「标题」”并回到标题；选择在本次悬浮窗运行期间沿用。
- 所有字段具有可访问标签；键盘焦点留在配置页内。沿用浅色/深色与中英文文案。

## 技术实施

1. Rust FloatingController 增加配置页模式的几何能力，保留原徽标外框，按当前显示器工作区与缩放居中；原有文本输入聚焦/归还机制保持权威。结束后恢复徽标与 Today 面板；显示器变化不能清除 React 草稿。
2. 通过生成绑定的 Typed IPC 暴露配置入口，更新命令登记、Capability、IPC 适配与测试替身。只开放完整创建和项目列表需要的权限。
3. 新增独立配置表单，FloatingRoot 在配置状态用它替换 Today 面板，停止原展开副作用。旧 QuickCreateForm 保留给原有独立调用。
4. 使用 createItem 一次提交完整配置，不采用“先建标题再更新”的两阶段写入，避免失败留下半成品。
5. 完成中英文文案、工作区几何与草稿/失败/取消/提交测试，再执行类型、Lint、格式、构建和受影响 Rust 检查。

## 验收

- 三种新增入口和托盘入口均进入完整配置页，位置为屏幕工作区中央，关闭后徽标原位置不变。
- 标题、简述、描述、格式、计划、截止、提醒、项目、优先级正确落入一次创建请求。
- 切换类型、窗口失焦和创建失败不丢草稿；取消不创建记录；重复提交不生成重复记录。
- 小窗口内容可滚动、操作可达；中英文和明暗主题可读，键盘与输入法可操作。
- 浏览器渲染检查与原生混合 DPI/多屏实机验收分开记录，不以 Mock 宣称原生通过。
