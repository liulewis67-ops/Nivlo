# 性能基线（实测）

测量脚本：`scripts/perf/measure.ps1`（实施计划 1.11 / 7.2）。测的是**已安装的 Release 构建**（NSIS 安装包安装后的 `nivlo-desktop.exe`），
全新的临时数据目录，进程树 = 主进程 + WebView2 子进程。

## 2026-10-12 · v0.1.1 · Windows 11（16 逻辑核）· 默认配置（无自定义皮肤）

| 指标 | 结果 | 预算 | 结论 |
| --- | --- | --- | --- |
| 冷启动到悬浮窗可见 | **378 ms**（另一次 447 ms） | 体感 < 1 s | 达标 |
| 空闲 CPU（10 分钟，进程树）平均 / 峰值 | **0.050% / 0.991%** | 平均 < 0.5% | 达标 |
| 内存（进程树工作集）起 / 终 | 379.8 MB / 511.4 MB（+34.6%） | 8 小时增长 < 10% | **未验证**（见下） |

内存曲线（逐分钟）：390 → 414 → 414 → **518（第 4 分钟一次性 +100 MB）** → 516 → 513 → 512 → 512 → 511 → 511。
10 分钟里只有一次台阶，之后持平略降，没有持续爬升；但 10 分钟不足以判断 8 小时的增长，

**台阶来源（逐进程复测，8 分钟，每分钟一次）**：Nivlo 主进程一直是 **38 MB（平的）**；WebView2 的浏览器 / GPU / utility 进程基本持平；台阶出现在第 7–8 分钟，是**多了一个渲染进程（renderer ×1 → ×2，+约 90 MB）并带动 GPU 进程 +20 MB**。多出来的渲染进程在两次测量里出现的时间不同（第 4 分钟 / 第 8 分钟），符合 Chromium「备用渲染进程」（spare renderer）的预热行为，但没有用 `--type` 之外的信息进一步确认它不是应用自己创建的第二个窗口。结论：**Rust 进程没有增长迹象，增长来自 WebView2 进程；8 小时长稳测试（`-Minutes 480`）仍然没做。**
