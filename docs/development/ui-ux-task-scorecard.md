# UI/UX task scorecard

Date: 2026-11-02. Status: **not run**. Participants: none. Baseline participant sessions: unavailable. The user requested proceeding with available checks and documenting gaps; no automated timings below are substituted for participant task results.

Recruit 5–8 first-time and practiced desktop users, including keyboard/low-vision experience where possible. Give the same task and fixture before/after. Start timing when the task/content is handed over; stop at the correct persisted result and focus destination. Record first-use separately from practiced trials. Do not coach; record any assistance as assistance rather than unassisted success.

| Task script | Correct outcome | Practiced target | Actual success/time/ease |
| --- | --- | --- | --- |
| Capture the supplied text, URL and file from a source app, then resume that work | Exactly one intended item, correct type/source/path, focus returned to source | 15s for text capture | Not run |
| Organize the named Inbox item into the specified project and planned date | Correct identity/project/scheduled date; due date remains distinct | 30s | Not run |
| Find the specified similar-prefix calendar item and move it to the requested day | Correct identity/date, retained time and due date | 30s | Not run |
| Search for and open the known item | Immediate typing, intended result and editor focus | 15s | Not run |
| Complete/delete/reschedule, wait until the toast expires, then recover | Persistent alternative remains discoverable and restores the intended state | Record baseline | Not run |
| Edit, inject a failed save, attempt to leave, then recover and retry | No silent draft loss; latest draft saved and transition occurs once | Record baseline | Not run |

For each participant/task, record: first-use/practiced, exact success, elapsed seconds, action count, wrong targets, backtracking, assistance, recovery outcome and ease 1–7. Report success as exact fractions and time/ease per task. Proposed goals are at least 90% unassisted success and median ease at least 6/7; a severe failure cannot be hidden by the aggregate. With no sessions, neither goal has an observed result.

Keep real-source app checks distinct: Chrome/Edge/Firefox/VS Code/Word/Explorer each need their own OS/app/version, payload, action, observed format/result and focus-return record. Generic Win32 clipboard/OLE harness results do not fill those rows. Link any future sessions to the [stage ledger](ui-ux-progress.md) and [evaluation plan](ui-ux-evaluation-plan.md).
