# Nivlo 待办体验设计

## 用户在什么情况下需要它

用户正在聊天、浏览网页、看文件或处理今天的工作。看到一件需要跟进的事时，可以先收下来，也可以当场决定哪天做。之后应能凭标题、原文或关联资料找回它。这里以 Windows 桌面端为设计范围，优先复用悬浮窗、收集箱、新增配置和日历。

当前悬浮窗已有「新建事项…」和「直接收进收集箱」两个拖放区。收集箱支持主动粘贴。悬浮窗的文本拖放会用首行预填标题，多行时保留全文。新增配置本身已有计划日期、截止日期和关联资料，待办通常默认计划在今天。以下交互及文案为设计提案。

## 场景与交互

| 用户正在做什么 | 从哪里操作 | 界面应当如何响应 |
| --- | --- | --- |
| 在 IM 里看到一句行动项，想马上记下 | 复制 IM 消息，在收集箱按 Ctrl+V，或点悬浮窗「粘贴到收集箱」 | 一次创建一条未排期待办。「已收进收集箱」反馈附「查看」「撤销」。下次仍可用相同动作收另一条。 |
| 一段群聊里有时间、讨论和链接，保存前想改标题 | 直接选中文字后按「从选区或剪贴板新建」快捷键；也可以先复制再按同一个快捷键 | 打开新增弹窗并自动预填标题和消息原文。日期需主动确认，链接可作为关联资料，用户可修改或移除。 |
| 从网页、编辑器或支持拖放的 IM 里拖出一段选中文字 | 拖到悬浮徽标，再移到「新建事项…」 | 悬浮窗展开并显示两个放置目标。松手后进入预填表单，文字默认建议「待办」。若源应用只允许复制，走上面的粘贴路径。 |
| 会议期间连续收集多条消息，晚些再整理 | 逐条拖到「直接收进收集箱」，或重复粘贴到收集箱 | 每次动作单独反馈，悬浮窗与主窗口保留原来的工作位置。「撤销」只作用于该条反馈对应的提交。 |
| 从浏览器拖来 Jira 链接，或从资源管理器拖来待审文件 | 拖到悬浮窗的配置区；也可在已有待办配置中拖入 | 独立链接或文件默认建议「笔记」，可在同一表单切换成「待办」并保留关联。在已有草稿上拖入时追加关联资料，保留已编辑字段。 |
| 任务已经在收集箱，确认周五才有空 | 把已有待办拖到日历当天，或在「整理」菜单选择「安排日期…」 | 更新同一条待办的计划日期，反馈「已安排到 11 月 20 日」和「撤销」。保留原来的截止日期、提醒与资料。 |
| 想把外部内容直接安排到某一天 | 拖一段可用文字到日历日期，也可在该日期的「新建」入口导入剪贴板 | 打开同一表单并显式预填目标日期。日历外部放置放在第二阶段，先用日期入口覆盖鼠标和键盘路径。 |
| 截图里有需要处理的问题 | 从截图工具复制图片后粘贴到收集箱 | 沿用图片捕获，再通过「整理 → 转为待办」补标题。若提供在待办配置里直接导入图片，保存确认前要展示图片及其保存方式。 |
| 做完后需要把结果发回原来的讨论 | 从「今天」或全局搜索打开事项，查看消息原文与关联 | 只有可靠可用的关联才显示「打开来源」。普通文本粘贴来源显示为「剪贴板」，消息里的链接显示为关联网页。 |

## 界面与文案

### 悬浮窗与收集箱

- 徽标的提示写「拖入文字、链接或文件」。拖拽进入后展开面板，只高亮当前目标。预填区显示「松手预填事项」，直接收集区显示「松手收进收集箱」。读取内容后再显示建议类型。拖出、按 Esc 或在窗口外松手时恢复原样。
- 保留上方预填区和底部「直接收进收集箱」。悬浮面板显示「粘贴到收集箱」作为快速入口。在收集箱的工具栏保留对应的可点击动作，在空状态展示一次简短示例「从聊天复制消息，再回到这里按 Ctrl+V」。
- 空白区 Ctrl+V 才触发收集；输入框、富文本、筛选和具有编辑焦点的弹层正常粘贴。按住快捷键产生的重复触发合并为一次。用户松键后主动再次粘贴时，保留该操作。

### 新增配置

原有新增配置承载鼠标拖放和显式导入。首屏放标题、类型、去向和创建动作。完整消息紧随标题，可展开，关联资料与详细日期按需展示。

```text
新建待办                             从剪贴板导入
标题    把新版报价发给客户
去向    [收集箱]  今天  选日期…
内容    查看原消息（3 行）
关联资料    报价文档                 移除
                             取消    创建待办
```

- 从悬浮窗配置区拖入或显式导入的外部待办默认去收集箱。日历入口优先采用目标日期。表单已有用户选择的类型、标题、日期或项目时，后续导入保留这些选择；导入前展示将追加的内容。手动新建沿用现有默认行为。
- 去向是创建后的可见结果。「收集箱」清空计划预填并建立未排期条目；「今天」和「选日期」更新计划日期，在对应日期的视图里可找到。截止日期和提醒各自在详细设置内确认。验收时以数据库和各视图的实际归属为准。
- 短的单行纯文本可直接作为标题。多行消息默认选首个非空行为可改标题，并保留消息正文、顺序、换行、链接，以及剪贴板实际提供的发送者和时间文本。若首行是转发抬头，用户可改标题，内容中的抬头仍可保留。首期一批消息形成一条待办，拆分由用户明确触发。
- 相对日期如「周五前给客户」只作为待确认建议。用户应用前可看到具体年月日，并选择「计划」或「截止」。两个字段一起出现时分别标明含义。文本含多条日期或引用过去的对话时，可直接跳过建议。
- 把消息作为纯文本处理。仅合法的网页 URL 可成为可打开关联。只有用户触发上下文快捷键、导入或粘贴时才读取剪贴板。消息原文留在本地事项内，诊断和体验测试使用合成消息。

### 全局快捷键「从选区或剪贴板新建」

在「设置 → 快捷键」增加独立动作，候选默认键为 `Ctrl+Alt+Shift+Space`，正式绑定以真机冲突验证为准。沿用现有的改绑、停用、恢复默认和冲突提示。原来的 `Ctrl+Shift+Space` 仍可用于常规快速创建。

| 按下快捷键时的情况 | 创建弹窗的行为 |
| --- | --- |
| 前台应用有可读取的非空文字选区 | 预填选中文字。在标题旁标明「来自当前选区」。选区可以由鼠标或键盘产生。 |
| 无文字选区，或前台应用无法提供选区 | 读取本次触发时可用的剪贴板文本并预填，标明「来自剪贴板」。剪贴板内容可能早于当前窗口，用户可以直接编辑或清除。 |
| 选区与剪贴板均无可用文本 | 打开空白弹窗并聚焦标题。根据情况提示「选中文字，或复制消息后再试」或「暂时无法读取剪贴板」，也可继续手动填写。 |
| 创建弹窗已有编辑内容 | 聚焦已有弹窗，提示「追加到内容」。用户确认后才追加，原有标题、日期、项目和关联保留。 |

短文本填入标题，多行文本取首个非空行作可编辑标题，并在内容区域保留原文。导入成功后焦点在标题，默认去向为「收集箱」。按「创建待办」才保存，Esc 关闭空白或尚未编辑的预填弹窗，焦点回到原应用。弹窗打开后仍可用「从剪贴板导入」显式改用剪贴板内容。

Windows 实施从触发时的前台窗口读取选区，先记住源窗口和控件，再切换焦点。支持的文本控件可通过 UI Automation 的 `TextPattern.GetSelection` 读取当前选区。首期覆盖可读的纯文本选区和剪贴板文本，含作为文本提供的链接；图片、文件走既有收集入口。选区读取设置时限，超时走剪贴板回退；已取消或被新触发替换的请求丢弃结果。读取全程保持系统剪贴板原样，密码控件的选区跳过。应用兼容性逐个实测。 [Microsoft 的选区接口文档](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern-getselection)

## 状态、恢复与键盘

| 状态 | 可见反馈及动作 |
| --- | --- |
| 正在读取或保存 | 对应动作显示「正在读取…」或「正在创建…」；同一次操作挂起时避免重复提交。读取结束之前允许离开，过期结果丢弃。 |
| 剪贴板为空或源应用不提供可读内容 | 分别显示「先复制一条消息，再粘贴」与「无法读取此内容，试试复制文字或链接」。当前草稿保持可编辑。 |
| 剪贴板暂时被占用 | 显示「暂时无法读取剪贴板」和「重试」。重试由用户触发。 |
| 用户已有草稿 | 如标题为空可预填。已有标题或原文时，明确提示「追加到内容」并要求确认，保留用户原先输入的文字。取消追加回到原编辑位置。 |
| 附件取不到路径或超过上限 | 写清失败的那项或未加入的数量。可移除后重试；取不到路径时提示尝试从资源管理器复制文件，使用收集箱粘贴。 |
| 保存失败 | 表单内显示原因和「重试」，保留所有字段、选择和关联；当前新增配置继续持有焦点。 |
| 创建或排期成功 | 反馈包含事项标题或去向，可「查看」和「撤销」。查看按事项 ID 定位，即使列表有筛选。撤销创建采用已有回收机制；撤销排期恢复之前的安排。多次操作的撤销以各自的提交为准，避免覆盖后续编辑。 |
| 来源文件后来移动或删除 | 详情仍能显示事项和记录的原路径，打开失败时在该关联旁反馈。 |

「粘贴」「选日期」和行级「整理」提供拖放的等效路径。输入法组字时 Enter 继续由输入法处理，确认后才会提交；Esc 优先退出正在进行的拖放或选择，编辑过的草稿仍遵循已有放弃确认。读屏能拿到控件名称、目标日期和操作结果。焦点进入配置时落在标题，关闭时回到原入口，跨应用唤出的窗口取消后回到原应用。布局沿用现有中性色和组件，紧凑宽度下去向按钮换行，创建与取消随 Tab 可达。

## 实施顺序

| 优先级 | 交付与复用 |
| --- | --- |
| 第一阶段 | 给已有入口补动作和结果文案；把显式剪贴板文本导入接到新增配置。复用 `InboxPage`、`usePasteCapture`、`FloatingRoot`、`useDropCapture`、`CreateConfiguration` 与已有捕获撤销。显式导入需要可读取草稿文本的窄范围 IPC；现有 `captureFromClipboard` 会直接落库，继续用于收进收集箱。创建请求复用 `create_item`，核验目标归属能与事项写入一起提交。 |
| 第一阶段 | 注册独立的「从选区或剪贴板新建」全局快捷键。复用原生快捷键注册和创建弹窗唤起路径，通过同一套文本预填规则接入选区读取和剪贴板回退。给预填结果增加入口来源和一次性的请求标识。 |
| 第二阶段 | 完善日历日期入口和外部拖放、已有待办的排期菜单、可确认日期建议。复用日历排期能力、`DatePhraseChip`、详情日期字段与项目选择。内部待办拖动携带事项 ID，外部内容生成草稿，落点样式共同表达具体日期。 |
| 后续验证 | 观察多消息拆分、图片转待办、回跳 IM 的需求。先采集目标 IM 版本实际支持的复制和拖放格式，再决定是否提供产品级的回跳能力。 |

## 验收任务

| 给参与者的任务 | 验收证据 |
| --- | --- |
| 从微信、企业微信或飞书复制三行群聊，先收下，再找回来 | 逐应用在 Windows 真机记录版本、剪贴板格式和实际结果。一次粘贴只出现一条待办，可用原标题找回，打开能查看消息原文。 |
| 先复制「旧消息」，再选中「新消息」按全局快捷键 | 在支持选区的应用预填「新消息」，来源显示为当前选区。换到不提供选区的应用，复制正文后可通过同一快捷键预填。覆盖剪贴板为空、内容冲突、选区超时、快捷键冲突及已有草稿；关闭弹窗后焦点回原应用，剪贴板仍保留旧内容，确认前数据库无新增事项。 |
| 把一段文本、一条链接、一个含中文和空格的文件拖到悬浮窗 | 上方目标能预填且允许切换类型，下方目标可直接收下并撤销。浏览器、资源管理器与 IM 有独立实测记录。 |
| 从消息创建一条周五做、下周一截止的待办 | 用户能在保存前核对两个日期；在日历只改计划日期后，截止仍为下周一。键盘完成同样的排期和撤销。 |
| 先写一半，接着粘贴新消息，模拟一次保存失败后重试 | 已改标题、计划和原文均保留，用户识别何处会追加，重试后只有一个新条目。 |
| 用键盘、中文输入法与读屏完成捕获和撤销 | 无需拖放即可完成核心任务；组字 Enter 不提交；焦点返回可预期；轻量反馈可读。至少人工覆盖 Windows NVDA、200% 缩放和浅色/深色主题。 |

第一轮观察记录首次发现入口的情况、从复制或开始拖动到保存的操作次数、错误去向、消息原文缺失和重复条目。发布门槛为本轮验收范围内的功能与恢复行为均可重复通过。微信、企业微信和飞书的独立真机验收按用户决定暂缓。耗时和入口偏好先记录基线，再据实决定是否调整默认入口。

## 实施与验证记录

- 全局快捷键、显式剪贴板导入、两个悬浮窗放置目标、日历日期入口和收集箱的「安排日期…」均已接入。快捷键默认组合为 `Ctrl+Alt+Shift+Space`，可以在设置中更改。导入表单保留原文与来源，选择去向后随事项一起提交。日期建议需分别确认，改期撤销会先核对操作后的事项版本。
- 前端回归覆盖已编辑草稿的追加、取消追加后恢复光标、失败重试、输入法组合事件、重复粘贴、日历落点和指定日期撤销。全量 Vitest 通过 764 项。Rust 应用层 148 项和能力权限 7 项通过。快捷键另有 5 项测试覆盖选区优先、读取超时和取消后丢弃结果。
- Windows 真机使用带文本选区的 WPF 窗口验证快捷键预填、剪贴板未改动、取消后焦点归还、保存后收集箱原文与来源，以及撤销移入回收站。重跑可用 `node tests/e2e/e2e.mjs --native --context-create-only`，通过 `NIVLO_EXE` 指定本次构建。
- 浏览器渲染场景验证了浅色、深色、400px 窄窗、保留失败草稿和固定底栏。已更新新增配置的七张截图基线，其中两张覆盖剪贴板预填。重新对比的像素差异均为 0%。Windows 主窗口详情与全局搜索的 200% WebView2 缩放回归通过。
- Windows 原生 OLE 专项连续通过两轮。WPF 辅助窗口在真实鼠标按下后发起拖放，验证普通文件、带中文和空格的文件、文件夹、文本和网址可拖入收集箱，文件引用路径正确，文字捕获可以撤销。文本拖到上方放置区只预填标题，确认前没有写入事项。重跑可用 `node tests/e2e/e2e.mjs --native --ole-only --runs 2`。
- 扩展后的 OLE 专项通过。主窗口禁用 Tauri 的原生拖放处理器，让 WebView2 传递日历需要的 HTML5 事件。真机拖入两行文本后按落点日期预填，确认前未写入事项。确认后计划日期与原文正确，实际按下 `Ctrl+Z` 把新事项移入回收站。前端另验证主窗口普通页面拦截文件和链接导航，文本编辑器和文件选择框保留对应输入行为。
- Chrome 157.0.8103.52 独立窗口连续通过两轮真实鼠标拖放。在本地测试页拖住网页链接并松到悬浮窗上方，确认前数据库无新增。把预填的条目切换成待办后，完整网址仍作为来源保存。重跑可用 `node tests/e2e/e2e.mjs --native --browser-drop-only --runs 2`。

### 后续 IM 真机验收步骤

验收可在各客户端的测试会话中使用同一条合成三行消息，分别执行以下操作。每次保存后按标题在收集箱找回，核对完整原文，并在下一轮前撤销或移除测试事项。

1. 复制消息，在收集箱空白区按 `Ctrl+V`。核对只新增一条待办，再记录客户端版本和这次复制提供的剪贴板格式。
2. 复制消息，在客户端仍处于前台时按 `Ctrl+Alt+Shift+Space`。核对标题是第一行、正文保留三行、来源为「剪贴板」，点击「创建待办」后再检查收集箱。
